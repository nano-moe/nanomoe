Demo Day / Hull Attention

Scaling the "LLMs as Computers" idea through fast attention.

We used ListOps as a controlled testbed to scale up the 2D attention story: same model width, same parameter count, different head geometry. The goal was not just to train a new variant, but to learn where the speed wins are actually lost inside a real system.

Current End-to-End Gap
15.6x slower
ListOps, 4 GPUs, batch size 64 per rank: hull is far slower than dense SDPA inside the full training loop.
Main Takeaway
Integration, not theory
The kernel story looks much better in isolation, so the real problem is likely dynamic-shape behavior and eval fallback paths.

What We Built

Experiment Frame Take the Percepta "LLMs as Computers" direction and push it into a larger, more operational setup using Long Range Arena ListOps.
Baseline Encoder-only Transformer classifier with dense SDPA attention, d_model=128, num_heads=8, head_dim=16.
Hull Variant Same model width and same parameter count, but repartitioned into 64 heads with head_dim=2, backed by QuACK hull attention.
Masking Change The integration now passes seq_lens into QuACK instead of a dense broadcast mask, which is the right interface for padded ListOps batches.

What We Learned

Training works

The QuACK-backed hull path trains end-to-end on ListOps and can handle large training batches.

Evaluation is still fragile

The sparse topk=1/4 eval path still falls back to a heavy reference implementation, which is why large eval batches fail.

The gap is not the whole story

Standalone kernel behavior looks much better than the end-to-end model run, so the current slowdown is likely coming from integration overhead.

Best next step

Stabilize sequence shapes or bucket lengths, then instrument QuACK path selection and compile misses before doing deeper kernel retuning.
